# 森林願望與森之露 UIUX 設計及審查

## 狀態與責任

2026-11-05。對應 [第一輪需求](forest-wishes.md)。此文件是 UIUX 交付給 PM 與 RD 的實作設計；正式程式由 RD 修改。首願望獎勵 25、裝飾價格 20／35／50 與 RD 對齊，其餘獎勵以最終實作及 PM 規格為準。已完成源碼審查與離線場景圖檢查，尚未有實作後瀏覽器驗證。

## 玩家流程與布局

進入森林 → 看見當前願望 → 依提示照顧 → 願望標為可領取 → 主動領取森之露 → 打開佈置森林 → 選擇購買或存錢 → 放進森林 → 看見場景改變。

- 願望區置於生態瓶畫布與世界標題之前。桌面與手機均先看到目標再操作，不把新手目標藏在桌面側欄或手機頁面底部。
- 願望標頭包含「森林願望」「1 / 5」、收起／展開控制。主體呈現名稱、條件與數字進度、獎勵及單一主要動作。不要同時突出五個任務。
- 森之露餘額與「佈置森林」入口鄰近願望區；餘額是持續可見的文字，不藏在浮動提示中。格式「森之露 25」，不顯示小數。
- 願望可收起，仍保留當前名稱及「進行中／可領取／已完成」狀態。收起不改變進度、領取資格或模擬。重整可依 RD 存檔實作保留偏好。
- 商店使用原生 dialog，標題「佈置森林」、可見餘額及關閉按鈕。開啟後不遮蔽關閉操作，不增加第二層確認。
- 三件裝飾排列為三張卡。寬版可並排，窄版改單欄；每張有像素外觀預覽、名稱、用途描述、價格／持有狀態及操作。所有物件從一開始可看見，無待解鎖的假入口。

## 願望與文案

| 順序 | 名稱 | 條件與提示 | 進行中操作 |
| --- | --- | --- | --- |
| 1 | 準備一桌點心 | 讓森林有 12 株植物（新局 9 株，通常再補 3 株）。動態提示「再補 N 株植物，替居民準備點心」。提示：在居民附近種些苔蘚，讓點心近一點。曾達成的證據或既有森林里程碑亦保留資格。 | 種下苔蘚 |
| 2 | 居民開飯了 | 讓一位居民實際吃到植物。提示：在居民附近補種苔蘚，恢復時間，等牠吃一口。 | 種下苔蘚 |
| 3 | 夜裡的微光 | 至少 5 株植物時切到夜晚，讓森林運轉片刻。提示：植物足夠時，夜裡會亮起螢火蟲。 | 切到夜晚 |
| 4 | 佈置我的森林 | 購買並放置一件裝飾。提示：在「佈置森林」挑選裝飾，再放到瓶內綠色地面。 | 佈置森林 |
| 5 | 新生命報到 | 見證一次自然出生。提示：讓兩位同種居民靠近、吃飽，保持適當濕度與足夠植物，等待牠們準備好。 | 觀察居民 |

- 領取狀態：主要按鈕改成「領取 N 森之露」，條件旁標「願望完成」。只能領取當前願望；提前達成的證據保留，輪到時直接可領取。
- 領取回饋：「獲得 N 森之露。下一個森林願望已準備好。」餘額立即更新。不要自動開商店、切天氣、切工具或跳走，讓玩家仍有選擇。
- 最後一項領取後：「五個願望都完成了。接下來，繼續照顧與佈置你喜歡的森林。」提供「佈置森林」操作；不呈現已停住的進度條或未來功能入口。
- 願望快捷動作要直接執行對應工具選取／天氣，使用鍵盤操作時把焦點移到畫布或相關控制，不能只有視覺捲動。
- 目前若暫停且願望需模擬事件，應顯示「時間暫停中，繼續後居民才會進食／夜晚發現才會記錄。」不假裝等待就會前進。
- 第一項若有既有 12 株以上的存檔直接符合，不要求先刪除或新增。新舊里程碑保留，不強迫已完成的夜晚與出生重做。

## 森之露資訊

主要說明：「健康的植物與吃飽的居民，會慢慢累積森之露。不同種類也會帶來更多收穫。」

補充說明：「暫停或離開頁面時，森林也會休息。森之露會隨時間流速一起累積。」

- 餘額為 0 也正常顯示；附近顯示「完成願望也能獲得森之露」，不使用警告色。
- 金額每次整數變化即可更新，不逐影格朗讀。`aria-live` 僅用於領取、購買、放置、取消與錯誤等離散結果。
- 不把森之露叫「能量」，不在玩家流程暴露存檔欄位、公式或偵錯資訊。產量規則若需說明，以實際健康／飽足條件和同種上限為準，避免「越多越好」的誤導。

## 裝飾與購買狀態

| 名稱 | 價格 | 外觀與短句 |
| --- | --- | --- |
| 蘑菇小燈 | 20 | 紅棕傘蓋、米白短柄與暖黃點光；「給林間添一點暖光。」 |
| 林間木牌 | 35 | 小木柱與葉形／箭頭木牌；「替小路留一個方向。」 |
| 石頭小徑 | 50 | 3 至 4 顆低矮暖灰踏石；「鋪一段慢慢走的小路。」 |

燈光是裝飾，不暗示增加日照或資源；小徑不暗示改變居民移動。三者皆不影響生態。

| 狀態 | 呈現與操作 |
| --- | --- |
| 未擁有、餘額足夠 | 「購買 · N 森之露」；按下後立即扣款、變成已擁有，原位置保留，不自動關閉商店 |
| 未擁有、餘額不足 | 購買按鈕 disabled；旁邊可見「還差 N 森之露」，不要只靠按鈕淡化說明原因 |
| 已擁有、未擺放 | 標記「已擁有 · 尚未擺放」，主要操作「放進森林」；沒有再購買按鈕 |
| 已擁有、已擺放 | 標記「已擺放」，操作「重新擺放」「收回」；重擺與收回免費 |
| 全部已擁有 | 三張卡仍可操作位置；提示「裝飾都收齊了，換個位置也會有新風景。」 |

購買回饋：「已擁有蘑菇小燈，可以現在放進森林，也可以稍後再擺。」關閉商店不失去未擺放物件。收回回饋：「已收回蘑菇小燈，隨時可以再擺放。」收回不退還森之露，因物件仍保留。

## 放置、重擺與取消

- 選「放進森林／重新擺放」才關閉商店並進入該物件的放置模式。畫布焦點可見，操作提示「正在擺放蘑菇小燈 · 點綠色地面放下」，並提供實際可點的「取消擺放」控制。
- 鍵盤沿用方向鍵移動游標、Enter／Space 放置，Esc 取消；可見提示包含鍵盤方式。使用者不需滑鼠才能完成首次佈置。
- 滑鼠在合法地面顯示半透明預覽；觸控不依賴 hover，點合法位置即可擺放。違法位置提示「請放在瓶內的綠色地面」，模式繼續，餘額與物件保持。
- 重擺期間保留原物件位置，只有新位置成功後才取代。取消、切換生物工具或關閉頁面不讓物件消失。
- 成功後回到觀察模式，提示「蘑菇小燈擺好了。想換位置時，打開佈置森林。」避免後續點擊連續移動。
- 收回只移除擺放位置，保留擁有狀態及首次佈置達成紀錄。
- 裝飾與生物依深度共同排序，照片包含裝飾。裝飾操作從商店卡進行，不能蓋住生物後讓玩家再也點不到居民。

## 視覺與無障礙

- 沿用紙白底、森林綠文字、自然像素預覽。新願望區以柔綠底區隔，完成狀態以文字＋圖示呈現，不只換顏色。
- 新區域內文 14px、行高至少 1.6；價格與次要資訊至少 12px。不要沿用現有 8px 補充字級到重要任務條件。
- 新可操作控制高度至少 44px；主要按鈕深綠底配近白字，次要按鈕使用描邊或文字加足夠留白。卡內間距 12～16px，區塊內距桌面 20px、手機 16px。
- 窄版 320px 起不橫向溢出；餘額列允許換行，商店改單欄，dialog 高度不超出可視範圍並可垂直捲動；關閉按鈕可到達。
- 願望收合使用 button 的 `aria-expanded` 與 `aria-controls`；可領取提示不因收合消失。移除／新增卡片內容時維持合理焦點，不每次模擬更新重建有焦點的按鈕。
- dialog 打開時焦點進入，關閉後回到入口；若關閉是為放置，焦點改到畫布。鍵盤焦點環不能被外框裁掉。
- 裝飾預覽提供名稱文字，像素 canvas 可設為裝飾性 `aria-hidden`；購買控制可及名稱包含名稱與價格，避免讀屏只讀到三個相同「購買」。
- 減少動態模式下不新增跳幣、閃爍、鏡頭移動或強制平滑捲動。一般模式也不增加必要等待動畫。

## 重建與存檔文案

重新種一瓶的確認文字改為：「目前的森林、日記、願望進度、森之露與裝飾將被新森林取代。可以先拍張照，留住這個小世界。」

既有保存狀態繼續可見；不把購買說成雲端永久保存。舊存檔安全補欄位，不向玩家顯示技術遷移文字。

## 審查清單與證據

以下為待驗證清單，尚非通過宣告：

1. 桌面與 390px 窄版首次進入，無需捲到頁底即可理解下一步，且看得見畫布。
2. 首願望完成／領取一次、提前進食／夜晚紀錄、完成後前進及全部完成狀態。
3. 零餘額、不足、足額、已購未擺、擺放中、取消、已擺、收回及全部購入。
4. 全鍵盤開商店、買、選放置、移動、放下、重擺、Esc 取消與關閉 dialog 的焦點。
5. 點天空無效、重擺取消保留原位置、手機點擊放置，以及場景／照片中裝飾可見。
6. 重整後進度與擺放保留；重建說明完整；暫停不讓提示誤導玩家。
7. 320px／390px／桌面無橫向溢出，長提示不蓋住主要操作；減少動態模式不新增動效。

實作審查結果由 UIUX 後續補在本節。原始碼檢查、離線渲染與瀏覽器實際操作分開記錄。

### 2026-11-05 實作審查結果

審查範圍：`dist/progression-ui.js`、`app.js`、`index.html`、`style.css`、`progression.js`、`decorations.js` 與 `render.js`。以下為源碼可確認的結果，不能替代實機互動測試。

- 願望區位於生態瓶前，願望名稱、狀態、獎勵、收合、餘額與商店入口完整；首願望動態說明「再補 N 株植物，替居民準備點心」。完成證據保留，僅當前願望可領取，全完成後有繼續佈置入口。
- 商品卡使用穩定 DOM 更新；購買按鈕可及名稱包含物件與價格。不足額顯示差額、已收藏未擺放／已擺放狀態清楚。買後留在 dialog，再選放置才進畫布；收回後焦點明確回到該卡操作。
- 放置沿用鍵盤地面移動與 Enter／Space，另有 Esc 及可見取消按鈕；未放置或重擺取消不清除擁有／舊座標。完成放置回觀察。新裝飾不加入生物選取候選，因此不會阻擋既有居民選取。
- 源碼包含 540px 單欄商店、可換行區塊、dialog 90vh 捲動限制、新控制至少 44px 與減少動態樣式。視窗實際溢出、文字折行與 dialog 焦點仍待瀏覽器驗證。
- 重建確認文字包含願望、森之露及所有裝飾。開店會清除上次通知，避免重建後出現先前購買成功的舊提示。

審查提出並由 RD 修正，已複查源碼：

1. 暫停時，未完成的進食／夜晚／出生願望改顯示「時間暫停中，按 ▶ 繼續後才會記錄進食、夜間發現或自然出生。」
2. 商店 `aria-live` 成功文字改為僅內容變更才更新，避免每次 UI tick 重寫；開店清空舊通知。
3. 產率從容易與遊戲 MIN 刻度混淆的「每遊戲分鐘」改為「1× 時每分鐘約 N 森之露 · 目前 X×」。

離線視覺證據：已逐一開啟檢查 `artifacts/wishes-sunny.png`、`wishes-night.png`、三張 `wishes-preview-*.png` 及 `wishes-photo.png`。蘑菇小燈、林間木牌、石頭小徑在晴／夜場景可辨識，與原生態瓶像素風格一致；三種半透明放置預覽與地面標記可見。照片檔僅為 960×700 的場景輸出與保留標題區邊界檢查，未合成最終文字區，不能稱為已驗證瀏覽器下載照片。

截至此輪未發現仍須阻擋交付試玩的 UIUX 源碼或離線場景圖問題。建議進入使用者試玩，重點觀察第一次領獎與買後放置是否容易理解、窄版願望高度是否合適，以及繁殖等待是否使玩家失去方向。

仍未驗證：桌面與 320px／390px 的實際 DOM 版面、觸控、dialog 原生焦點返回、實際鍵盤完整流程、讀屏、瀏覽器下載與實際 localStorage 操作。PM 回報瀏覽器 host 不可用，原生 Edge 工具無法可靠辨識網址；本輪沒有以替代操作繞過此限制。
